# 工程规范（v1 · C 语言）

> **继承关系（不另立一套）**
> - 提交骨架、type 白名单、三段正文、自检清单 → 沿用 `~/Embedded/stm32_module_lab/CONTRIBUTING.md`；
> - 注释三层模型（模块 / 函数 / 实现）、`/**` 才算文档注释 → 沿用同目录 `STYLE.md`（你实测过 clangd 行为）。
>
> **本文只写本项目新增或收紧的部分。与那两份冲突时，以本文为准。**

---

## 一、提交规范

### 1.1 骨架（继承）

```
<type>(<scope>): <描述>

Why:      改之前哪里不对（一句话）
Verified: 怎么证明没坏（命令 + 结果）
Left:     已知未做 / 风险 / 下一步入口（没有就写 none）
```

### 1.2 本项目 scope 白名单（只增不改）

| scope | 覆盖范围 |
|---|---|
| `bus` | `sdk/bus.*` 总线路由 |
| `dm_motor` | `devices/dm_motor/`（协议层与位置迁移） |
| `port` | `port/inc`、`port/mc02`、`port/host` |
| `sched` | `sdk/sched.*` |
| `err` | `sdk/err.h` 错误码 |
| `config` | `sdk/config.h` 容量与开关 |
| `app` | `app/` 业务 |
| `build` | CMake / 预设 / 工具链 |
| `docs` | `docs/` 下的契约与协议 |
| `rules` | 本文件与审查脚本 |

### 1.3 提交粒度的四条判据（可判，不靠感觉）

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | **能单独回滚** | `git revert <sha>` 后 `cmake --build` 通过且 `./tests/host/run.sh` 退出码 0 |
| 2 | **一句话说完，不需要"以及"** | 标题里出现「以及 / 顺便 / 同时」= 该拆 |
| 3 | **≤ 3 文件 且 ≤ 100 行有效改动** | 超过必须能在 `Why:` 里说清"为什么不可拆" |
| 4 | **`Verified:` 是可复跑的命令** | 写"测试通过"不合格；写 `./tests/host/run.sh → 67/67, exit 0` 合格 |

> 判据 3 的 100 行是**经验阈值**，不是硬规则；判据 1、2、4 是硬规则。

### 1.4 反例（本项目真实发生过的）

```
❌ fix(config): 总线数改为 3，容量集中定容并补推导，并修正 .gitignore
   → 三件事混一条（判据 2）
❌ docs(contract)+feat(port): 双版本契约与 CAN 端口接口
   → type 写两个（规范外）
❌ 正文只有 bullet 列表，没有 Why/Verified/Left
   → 无法 grep 复盘（`git log --grep='^Left:'` 抓不到）
```

## 二、颗粒度：四层，每层有自己的判据

```
Epic    阶段目标          判据：能上板/能交付的一句话目标
 └ Slice  一刀（可测）    判据：一条命令能证明它成立
    └ Commit 可回滚变更  判据：revert 后仍绿（§1.3 四条）
       └ Step ≤30 min    判据：无（不单独提交，只为拆解用）
```

| 层 | 大小（经验） | 判据 | 本项目例子 |
|---|---|---|---|
| **Epic** | 数天~数周 | 一句话交付 + 可上板 | 「J1 到位保持 < 1° + 三类保护」 |
| **Slice** | 半天~2 天 | **一条命令 + 输出**能证明 | 「`bus.c` + host 替身：68 条判据全绿」 |
| **Commit** | 1~3 小时 | §1.3 四条 | 「`feat(bus): 订阅表与 1:N 分发 + 6 条用例`」 |
| **Step** | ≤30 min | 无 | 「写 `Bus_Subscribe` 的重复检测分支」 |

**Slice 的硬要求**：完成时必须能贴出「命令 → 结果」。贴不出来 = 还没完成，只是"写完了代码"。

## 三、注释规范（继承 + 5 条硬规则）

### 3.1 每个头文件顶部固定三行

```c
/**
 * @file dm_motor.h
 * 解决什么：把达妙 MIT 帧翻译成物理量，并记住每条轴的在线状态
 * 不解决什么：轨迹、PID、总线仲裁（分别在 app / 电机内部 / bus）
 * 判据在哪：tests/host/main.c 的 t_mit_* / t_decode_* / t_state_decode
 */
```

### 3.2 五条硬规则

| # | 规则 | 违反的后果 |
|---|---|---|
| 1 | 公开函数写**七要素**：前置 / 后置 / 失败码 / 单位与时基 / 上下文（主循环？中断？）/ 幂等性 / 示例 | 调用方只能读实现猜语义 |
| 2 | `static` 私有函数**只写为什么**，不写 `@param`、不写"做什么" | 两份契约要同步，必然失同步 |
| 3 | **任何数字必须带推导**（容量、超时、阈值、位宽） | 半年后没人敢改（见 `sdk/config.h` 示范） |
| 4 | `/**` 才是文档注释；`/*` 工具不认（你实测过 clangd） | tooltip 空着，等于没写 |
| 5 | 文档里**不写行号**（`.c:142` 会漂移） | 一个月后指到别的地方 |

标签只用四个：`TODO(名字):` / `FIXME:` / `XXX:` / `HACK:`（继承 STYLE.md）。

## 四、C11 代码约束（v1）

| # | 约束 | 理由 |
|---|---|---|
| 1 | 不用 `malloc/free`，所有对象静态分配 | 长跑有界；碎片化调试成本远超收益 |
| 2 | 不用 VLA（变长数组） | 栈不可预知，嵌入式栈很小 |
| 3 | 头文件守卫 = `<模块大写>_H`，且只 include 自己需要的 | 减少编译耦合 |
| 4 | `static inline` 只放纯函数（无状态、无副作用） | 放状态会让每个编译单元各有一份 |
| 5 | 全局可变状态只允许"静态池 + 单一写者"，并在头文件注明 | 否则中断/主循环竞争无迹可寻 |
| 6 | 常量后缀 `u`/`f`（`32u`、`12.5f`），位宽用 `stdint.h` 定长类型 | 隐式转换警告即真 bug 苗头 |
| 7 | 只用 `bool`（`stdbool.h`），不用 `int` 冒充 | 返回值语义不混 |
| 8 | 不用编译器扩展（`__attribute__` 仅限已注释说明用途） | 换 GCC/Clang 不炸 |
| 9 | 每个 `.c` 文件只做一件事，函数 ≤ 60 行（超出先想拆） | 审查与单测友好 |
| 10 | `-Wall -Wextra -Werror` 是默认，不是"最后开" | 0 warning 是判据，不是愿望 |

## 五、审查协议（为你"从头审一遍"服务）

每个提交和每个文件都必须能回答这 5 问；答不上来就是规范没落地：

| # | 问题 | 答案写在哪 |
|---|---|---|
| 1 | 这一步**为什么做**（不做会怎样）？ | 提交 `Why:` 行 |
| 2 | **判据**是什么（哪条命令、什么输出）？ | 提交 `Verified:` 行 / 文件头第三行 |
| 3 | **依据**是什么（手册页 / 源码行 / 实测）？ | 文件内注释标注出处 |
| 4 | **没做什么**（已知缺口/风险）？ | 提交 `Left:` 行 |
| 5 | 违反哪条约束会怎样（症状）？ | `docs/契约-维护者版.md` 不变量表 |

> 因此从下个提交起：**`docs` 之外的所有提交，`Verified:` 必须是一条能复跑的命令。**

## 六、提交前自查（5 条，30 秒）

```
□ git revert 后还绿吗？（能单独回滚）
□ 标题里有没有"以及/顺便/同时"？（该拆）
□ Verified 是命令 + 结果，还是形容词？
□ 新建的文件带最小有效内容了吗？（不许占位）
□ Left 写了吗？（没有就写 none，不许省）
```

## 七、术语表（每个词第一次出现时用它解释）

> 规则：新增术语必须先进这张表，再在正文里用。不许用未定义的词。

### 7.1 颗粒度四层（§二 用的词）

| 词 | 是什么 | 不是什么 |
|---|---|---|
| **Epic** | 一个阶段目标，几天到几周，判据是"能上板/能交付的一句话" | 不是一个功能点 |
| **Slice** | 一次纵向切下来的"一刀"：从接口到能验证的完整一小段，半天到 2 天 | 不是"写了一个文件" |
| **Commit** | 一次可独立回滚的语义变更，1~3 小时 | 不是"今天干完的活" |
| **Step** | 给自己拆解用的最小动作，≤30 分钟，**不单独提交** | 不是对外可见的单位 |

### 7.2 总线（本仓库大量出现）

| 词 | 是什么 |
|---|---|
| **FDCAN** | STM32H7 的 CAN 外设名，既能跑经典 CAN 也能跑 CAN FD；名字带 FD 不等于在用 FD |
| **经典帧（CAN 2.0B）** | 数据段最多 8 字节，只有一个速率 |
| **CAN FD** | 一帧两个速率：仲裁段（nominal）+ 数据段（data，可数倍提速）；数据最多 64 字节 |
| **仲裁（arbitration）** | 多节点同时发时，按 ID 逐位比较，显性位(0)赢，所以**ID 越小优先级越高** |
| **位填充（bit stuffing）** | 连续 5 个相同电平后强制插 1 个反电平，用于同步；使实际帧长 ≠ 名义位数 |
| **DLC** | 数据长度码，帧里声明有几个字节 |
| **BRS** | Bit Rate Switch，FD 帧里"从这里开始切高速"的标志位 |

### 7.3 本仓库的设计词

| 词 | 是什么 |
|---|---|
| **订阅者（subscriber）** | 订阅了某个帧 ID 的回调 + 它的身份指针；一条订阅 = (id, 回调, self) |
| **静态池** | 编译期定好长度的数组，运行期只从中取，不 malloc |
| **不变量（invariant）** | 任何时刻都必须成立的条件；违反了就是 bug，不是"也许" |
| **幂等** | 调一次和调多次效果相同（本仓库只在设备命令上要求） |
