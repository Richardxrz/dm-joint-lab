## 一、规则 16 的 6 维在本项目怎么量

| 维度 | 上限（规则 16） | 本项目量法 | 超了怎么办 |
|---|---|---|---|
| 规模 | 净改动 ≤150 行；文件 ≤300；函数 ≤40；嵌套 ≤3 | `git diff --stat` + 数函数行 | 切下一轮 |
| 概念 | 新概念 ≤1；新抽象 ≤1 | 数"你没见过的新词/新接口" | 拆两轮 |
| 影响面 | ≤2 文件；只动 1 层；**公共接口不动** | `git status --short`；看 include | 接口变动独立一轮 |
| 依赖 | 新三方 = 0；内部依赖 ≤1；**不动构建系统** | `grep '#include'`、`git diff CMakeLists.txt` | 见 §十一 冲突 b |
| 复杂度 | 圈复杂度 ≤10/函数；新增全局状态 = 0；中断/线程/回调必须声明 | 人工数分支；声明写进 `Left:` | 拆函数 |
| 可验证 | **必须附 1 条可执行判据** | 命令 + 退出码 | 没判据不许提交 |

**「净改动」口径（待你确认）**：按 `git diff --stat` 的**新增行数**算，删除不计。
理由：删过时内容不该占预算，否则"改规范 / 删死代码"永远超限。

## 二、判据四级（每轮至少 L3）

| 级 | 判据 | 本项目例子 |
|---|---|---|
| **L1** | 构建通过、0 warning | `cmake --build build/host` |
| **L2** | 自测通过 | `./tests/host/run.sh` |
| **L3** | **行为判据**（帧字节/日志/现象符合预期） | `t_foreign_id`：B 拒收 A 的帧且 `foreign_cnt=1` |
| **L4** | 性能判据（周期/延迟/内存/总线负载） | 上板后 `Bus_Poll` 单帧分发 ≤20 µs；六轴 200 Hz 总线负载 ≤31% |

## 五、提交规范（骨架继承，数字改规则 16）

```
<type>(<scope>): <描述>

Why:      改之前哪里不对
Verified: 命令 + 结果（L2/L3）
Left:     未做 / 风险 / 下一入口（没有写 none）
```

- scope 白名单：`bus` `dm_motor` `port` `sched` `err` `config` `app` `build` `docs` `rules`（新增才追加）
- **一个提交 = 一轮里的一个语义单位**，预算按提交算

| # | 提交粒度判据 | 怎么验 |
|---|---|---|
| 1 | 能单独回滚 | `git revert` 后构建 + 测试仍绿 |
| 2 | 一句话说完 | 标题出现「以及/顺便/同时」= 该拆 |
| 3 | 落在 6 维预算内 | §一 表 |
| 4 | `Verified:` 可复跑 | 写"测试通过"不合格 |

反例（本项目真实发生过）：一条混三件事；`type` 写两个；正文只有 bullet。

## 七、注释规范（继承 STYLE.md 三层模型 + 5 条硬规则）

每个头文件顶部固定三行：**解决什么 / 不解决什么 / 判据在哪**。

| # | 硬规则 | 违反后果 |
|---|---|---|
| 1 | 公开函数七要素：前置 / 后置 / 失败码 / 单位与时基 / 上下文 / 幂等 / 示例 | 调用方只能读实现猜 |
| 2 | `static` 只写"为什么"，不写 `@param` | 两份契约必失同步 |
| 3 | **任何数字带推导**（示范：`sdk/config.h`） | 半年后没人敢改 |
| 4 | `/**` 才算文档注释（clangd 实测） | tooltip 空白 |
| 5 | 文档不写行号（会漂移） | 指向错位置 |

标签只用 `TODO(名字):` / `FIXME:` / `XXX:` / `HACK:`。

## 八、C11 约束（10 条）

不用 malloc ｜ 不用 VLA ｜ 守卫 `<模块>_H` ｜ `static inline` 只放纯函数 ｜ 全局可变状态仅"静态池 + 单写者"且注明 ｜ 常量带 `u`/`f`、定长类型 ｜ 只用 `bool` ｜ 不用编译器扩展 ｜ **函数 ≤40 行、嵌套 ≤3 层、圈复杂度 ≤10** ｜ `-Wall -Wextra -Werror` 默认开。

## 九、审查协议（你的 10 分钟）

**5 条**：① 契约（签名说的和做的对得上）② 行为（判据能复跑）③ 成本（RAM/CPU/总线负载）④ 可维护 ⑤ **可解释（你能白纸讲清；讲不清这轮不算数）**。

**不懂的领域三层**：契约层（能查）→ 行为层（能跑）→ 成本层（能估）。我给判据，你执行。
我只报「哪条判据不成立 + 依据」，不列缺陷清单、不指行号。

## 十、术语表（16 词；新词先来登记再使用）

**颗粒度**：Epic＝阶段目标｜Slice＝纵向一刀（能验证的半成品）｜Commit＝可回滚变更｜Step＝≤30 min 动作（不提交）。
**总线**：FDCAN＝H7 的 CAN 外设（带 FD ≠ 在用 FD）｜经典帧＝≤8 字节单速率｜CAN FD＝仲裁段/数据段两速率｜仲裁＝按 ID 逐位比、显性 0 赢、故 ID 越小优先级越高｜位填充＝连续 5 个同电平插 1 个反电平｜DLC＝数据长度码｜BRS＝FD 切高速的标志位。
**设计**：订阅者＝(帧 ID, 回调, self)；静态池＝编译期定长数组中取，不 malloc；不变量＝任何时刻必须成立的条件；幂等＝调一次和多次效果相同。
