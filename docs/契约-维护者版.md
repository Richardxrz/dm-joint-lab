# 契约 · 维护者版（模块之间怎么配合）

> 适用对象：改 `sdk/` 内核、加 `port/`、写检查脚本的人。
> 用户版在 `契约-用户版.md`。本文每一条都尽量配一个**机械检查方式**，人记不住的靠脚本卡。

---

## 一、依赖方向（只能向下，反向即违约）

```
app/  ──►  sdk/  ──►  port/inc（只有 .h）
                └──►  devices/  ──►  sdk/ + port/inc
port/mc02、port/host  ──►  port/inc（实现它）
```

| 检查项 | 命令 | 期望 |
|---|---|---|
| `sdk/` 不含 HAL | `grep -rn "HAL_\|stm32\|hfdcan" sdk/` | 空 |
| `port/inc` 不含实现 | `grep -rn "^{" port/inc/*.h` | 只有 `static inline` |
| `devices/` 不直连 HAL | `grep -rn "stm32\|HAL_" devices/` | 空 |
| `app/` 不 include port 实现 | `grep -rn "port/mc02" app/` | 空 |

## 二、不变量（违反后的症状写在症状列，便于反查）

| # | 不变量 | 违反后的症状 |
|---|---|---|
| 1 | **Bus 不解析载荷**：只按帧 ID 路由 | Bus 里出现 `pos`/`kp`/`0xFC` 之类，说明协议漏到内核了 |
| 2 | **分发不短路**：一个 ID 挂 N 个订阅者，全部调用 | 六轴里只有第一轴收到反馈 |
| 3 | **不依赖分发顺序**：同一 ID 的多个订阅者之间不得有先后依赖 | 单轴正常、加第二轴行为突变 |
| 4 | **静态容量**：所有表在 `sdk/config.h` 里定容，运行期不扩容 | 出现 `malloc`/`realloc`；或容量宏散落在各 .c |
| 5 | **不阻塞**：任何函数不 while 等、不延时 | 主循环周期抖动；`rx_drop` 增长 |
| 6 | **错误归属**：谁检测谁报，不越级 | 硬件错误被报成 `BUS`；或错误只写日志不返回 |
| 7 | **回调上下文 = `Bus_Poll` 内**，回调里允许 `Bus_Send`（入队，快）但**禁止**再调 `Bus_Poll` | 递归分发、栈溢出或重复计数 |
| 8 | **时间只从 port 取**：`sdk/` 里不出现 `HAL_GetTick`/`SysTick` | 换板子后时间基准变、host 测试拨不动表 |
| 9 | **所有权固定**：对象由调用方静态定义或由 SDK 静态池返回，SDK 内部永不 `free` | 出现 `free`；或谁 delete 谁说不清 |
| 10 | **累计量与瞬时量分开**：返回值只说本次失败；统计走 `*_GetStats` | 返回值里塞"累计错误数"，调用方无法区分 |
| 11 | **`EMPTY` 不是错误**：端口"暂时没帧"不得回报为故障 | 空闲总线上 `err_last` 一直非 0，真错误被噪声淹没 |
| 12 | **不认识的帧必须计数**：`rx_unknown` 只增，不静默丢 | 电机 ID 配错时表现为"完全没反应"，无从下手 |

## 三、错误归属表（谁检测 → 谁报 → 谁决策）

| 事件 | 检测方 | 报给谁 | 谁做决策 |
|---|---|---|---|
| 发送队列满 | `port/can` | `BUSY` → Bus 计 `tx_busy` | `app`（下拍再发 / 降频） |
| Bus-Off / 仲裁丢失 | `port/can` | `HW_FAULT` → Bus 计 `bus_off` | `port` 负责恢复，`app` 决定是否停轴 |
| FIFO 溢出 | `port/can` | 累计计数 | `app`（降频/缩短回调） |
| 帧无人认领 | Bus | `rx_unknown` | 维护者（订阅漏了） |
| 载荷里 ID 不是自己 | device | 设备自己的 `foreign_cnt` | device（拒收但可见） |
| 设备报故障态（ERR 0x8~0xE） | device | `fb.state` | `app`（三类保护） |
| 反馈超时 | device | `IsOnline(now)` | `app`（断使能） |

**规矩**：下层只报"发生了什么"，绝不做"要不要停电机"这类决策。

## 四、加一个模块/设备的 6 步

1. 定头文件契约（前置 / 后置 / 失败码 / 单位 / 阻塞与否 / 上下文）；
2. 数据全部静态分配，容量进 `sdk/config.h`；
3. 依赖只允许 `err.h` + `bus.h` + `port/inc`；
4. 写 host 侧规格测试，**先写失败路径**（参数非法 / 资源耗尽 / 重复注册 / 未初始化）；
5. 跑 `./tests/host/run.sh` + 四条 grep 检查；
6. 更新 `docs/契约-用户版.md` 的速查表（用户能查到的必须是最新的）。

## 五、v1 边界（越界即设计错误，不是"以后再说"）

| 不做 | 理由 |
|---|---|
| 动态内存 | 嵌入式长跑必须有界；碎片化问题调试成本远超收益 |
| CAN-FD | MC02 支持，但没有需求；现在加会让 port 契约复杂一倍 |
| 多总线并发调度 | 先单总线；容量宏留着，接口不变 |
| RTOS / 抢占 | 超循环 + 周期任务表够用；换 RTOS 时只动 `Sched` 与 `main` |
| 参数读写（`0x7FF` 协议） | 主机侧上位机的活，不进固件 |
