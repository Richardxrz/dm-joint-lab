# 契约 · 用户版（写给调用 SDK 的人）

> 适用对象：写 `app/` 业务的人、写 `devices/` 设备插件的人。
> 维护者版（模块之间怎么配合、不变量、扩展步骤）在 `契约-维护者.md`，你看那个没用。
> 版本：v0.1（2026-10-26）

---

## 一、你只能 include 这 4 个头

```c
#include "err.h"     /* 错误码 */
#include "bus.h"     /* 总线：发送、订阅、统计 */
#include "device.h"  /* 设备插件接口（待建） */
#include "sched.h"   /* 周期任务（待建） */
```

出现 `#include "stm32h7xx_hal.h"`、`hfdcan`、寄存器名 —— 说明你写错层了。

## 二、速查（语义 = 承诺）

| 函数 | 成功意味着 | 失败会怎样 | 你不能假设 |
|---|---|---|---|
| `Bus_Create` | 总线对象已绑定端口 | 返回 err，输出指针不变 | 能创建超过 `SDK_MAX_BUS` 个 |
| `Bus_Send` | **帧已交进硬件队列** | `BUSY`=这帧没发、`HW_FAULT`=硬件错 | 对端收到了（问询式，要等反馈） |
| `Bus_Subscribe` | 该 ID 的帧会回调你 | `NO_RESOURCE`=表满、`DUPLICATE`=重复订阅 | 回调顺序、回调一定先于别人 |
| `Bus_Unsubscribe` | 已摘掉 | `NOT_FOUND`=本来就没订阅 | — |
| `Bus_Poll` | FIFO 现有帧已分发完 | `HW_FAULT`=端口报错 | 它会等你、或会等你发完帧 |
| `Bus_GetStats` | 拿到同一时刻的快照 | `INVALID_ARG` | 两个字段来自不同时刻 |

## 三、你必须遵守的 4 条

1. **只在主循环调用**（回调里也算主循环）。ISR 里不许调 `Bus_Send` / `Bus_Poll`。
2. **回调要短**。回调跑 1 ms，主循环就慢 1 ms，`rx_drop` 就开始涨。重活丢给 `Sched`。
3. **`err` 不是 bool**。判断成功用 `e == SDK_OK`；打印用 `Sdk_ErrModule(e)` / `Sdk_ErrReason(e)`。
4. **不要依赖电机默认值**。MST_ID 出厂默认 0，但必须在开机自检里用寄存器 `0x07` 读回实际值再比对。

## 四、失败处理模板（照抄这三行就行）

```c
sdk_err_t e = Bus_Send(bus, motor_id, frame);
if (e != SDK_OK) {
  Sdk_Log(LOG_WARN, "BUS", "send id=%lu: %s/%s", motor_id,
          Sdk_ErrModule(e), Sdk_ErrReason(e));
  /* BUSY 不要重试——下一拍自然会再发；重试只会把队列压更死 */
}
```

## 五、三个反例（都真发生过）

| 反例 | 后果 |
|---|---|
| `if (Bus_Send(...))` 当成 bool 用 | `SDK_OK` 是 0 → 成功判成失败，逻辑全反 |
| `BUSY` 时 `while` 重试 | 队列更满、主循环卡死、`rx_drop` 暴涨 |
| 在 `on_frame` 里做浮点滤波 + 打日志 | 单帧耗时从 µs 变 ms，六轴直接丢帧 |

## 六、版本承诺

- 公开头里的函数与字段：改动前先改 `docs/CHANGELOG.md`；
- **破坏性改动**必须同时改 `devices/` 的用法示例；
- 新增函数可以，删/改语义不行（v1 冻结后按 semver）。
